# Agent instructions

This repository contains MS/MS structure elucidation skills and a Python CLI, `msms-structure-elucidation`. The skills are in `.agents/skills`, and `.claude/skills` links to the same folders.

- **Install or set up:** when asked to install these skills, or when `configs/local.yaml` is missing, follow the `msms-setup` skill. It checks the environment, asks whether models run on this machine or a remote host, probes that host, and saves the tuned ms-pred inference settings to `configs/local.yaml`. Do not commit that file.
- **Remote execution:** if `configs/local.yaml` has `execution.mode: remote`, run model-backed commands on that host as described in `msms-setup`.
- **Model tools:** when the `msms-structure-elucidation` MCP server is connected, call `server_info` first, then use its tools for predictions instead of running the model scripts directly.
- **Model and search selection:** use the intended prediction model and exact weights from a matching saved user confirmation, or ask once and save them; either ICEBERG's generator/intensity pair or a GLACIER checkpoint is sufficient. For ICEBERG, prefer suitable public atlas spectra unless fresh predictions throughout were requested. The atlas uses ICEBERG 2.1 trained on NIST'23; when local weights differ or matching weights are unverified, tell the user that combining their predictions may affect ranking comparability and label their sources. GLACIER predicts every candidate. For direct mass-only PubChem prediction, skip formula prediction, predict all eligible structures for every ppm-matched formula, and rank them together as described in `docs/technical-guide.md`.
- **Saved choices:** read [pipeline preferences](docs/pipeline-preferences.md) and `configs/local.yaml` before asking pipeline questions. Reuse matching user-confirmed answers and save new ones with `msms-structure-elucidation preferences`. Without a supplied feature list or saved feature-finder answer, ask once: GNPS2 Everything Bagel (recommended), msconvert + MZmine, or the user's own workflow. Scientific answers apply only to their recorded dataset/spectrum context.
- **Analysis:** follow [.agents/workflows/msms-elucidation.md](.agents/workflows/msms-elucidation.md). Before scoring, use the matching saved user confirmation for NCE versus absolute eV, or ask once and save it for the current dataset/spectrum.
- **Standards:** code, skills, workflows and research conduct follow `.agents/rules/`. For batch sizes and worker counts, use settings measured for the selected model in `configs/local.yaml`. The anchors in `msms-predict` are ICEBERG starting points; tune GLACIER independently on each machine using its native `pred_smis` configuration through the configured prediction path. The current GLACIER adapter uses one GPU worker.
