# Public atlas retrieval

If ms-pred setup is needed, use an existing checkout or clone [coleygroup/ms-pred](https://github.com/coleygroup/ms-pred) if absent. Read that checkout's `README.md` **Install & setup** section and follow its instructions for the host's supported CPU or CUDA option. Verify the resulting interpreter can import `ms_pred`, `msbuddy`, and `rdkit`, then pass it with `--ms-pred-python` or `MS_PRED_PYTHON`. `bash setup_envs.sh` is a CPU venv helper; check the upstream README before using it.

Ask the user what collision energies they supplied and whether the labels are NCE or absolute eV. Do not infer units from `.ms` headers or numeric values. Run `msms-structure-elucidation run --input sample.ms --collision-unit NCE --output-dir results/sample --formula C12H21NO5` when the user confirms NCE; use `--collision-unit eV` for confirmed absolute eV. Omit `--formula` to search the top three MSBuddy hypotheses, or use `--formulas-file` for a user list. MSBuddy tolerances default to the instrument (Q-TOF 10/20 ppm, Orbitrap 5/10 ppm precursor/fragment; `--ms1-ppm`, `--ms2-ppm` override; recorded as `mass_tolerance`). If MSBuddy proposes none, up to three formulas of PubChem structures within the precursor tolerance (CHNOPS by default) are searched instead and labelled as PubChem mass matches. The command downloads formula MGF files through the public `https://iceberg-ms.mit.edu/download_mgf` endpoint, converts NCE to eV, and pairs only equal rounded integer eV energies. If any atlas energy is missing, it predicts all atlas structures for that formula with local ICEBERG at every supplied energy, in resumable shards; provide `--ms-pred-dir` and ICEBERG checkpoints in [configs/default.yaml](../../../configs/default.yaml) or via CLI. It never ranks an off-energy atlas spectrum. `--atlas-mgf` accepts a local MGF for one formula. Inspect `status`, `formula_results`, all energy pairs, and `qc`. `needs_formula`, `no_atlas_coverage`, and `no_candidates` are valid empty results with exit 0. Missing model assets or operational failures exit nonzero and print the error. For `no_atlas_coverage`, `retrieval.json` records `next_step: iceberg-pubchem`; for a formula found neither by MSBuddy nor PubChem, `next_step: review-frigid`. Follow either with `msms-structure-review`. The public atlas excludes licensed NIST structures.

Entropy similarity and explained peak intensity are evidence, not identification probability. Explained intensity breaks near ties; flagged positional isomers may be indistinguishable from these spectra. Inspect unmatched high-intensity peaks and competing formula hypotheses. For GNPS/MZmine MGF, use `convert-mgf`; `SOURCE_SCAN` can point to MS1, so recover energies from actual MS2 scans or ask the provider. For Bruker Q-TOF, check precursor-specific absolute eV values in raw mzXML. For many features use `batch`. It processes several features at once when CPU and RAM permit, one worker process per feature, so atlas lookups run in parallel and overlap GPU model jobs. The worker count is `--max-workers`, or `models.batch.max_workers`: `auto` uses up to 8, sized from CPU threads and RAM at about 1.5 GB per worker, and `setup` saves a value. A new feature starts only while free RAM stays above `min_free_memory_gb`. Model jobs stay limited to `max_model_jobs`. Always launch `msms-visualize` and share its localhost URL as the primary result so the user can inspect and annotate predicted fragments; the basic `report.html` does not provide that interaction. Use `msms-structure-review` for new SMILES.
