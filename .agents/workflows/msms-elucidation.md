# MS/MS structure elucidation

1. For raw files, use `msms-preprocess`, `msms-inspect`, or `msms-feature-detect` to export a selected MS/MS feature in ms-pred `.ms` format. For GNPS/MZmine MGF, use `msms-structure-elucidation convert-mgf --input features.mgf --collision-unit eV --output-dir converted`; supply `--raw-mzxml` with the raw mzXML files or their folder to recover collision energies from referenced MS2 scans or, for GNPS exports that name only `SOURCE_FILE`, from that run's MS2 scans of the same precursor within `--ms2-rt-window` seconds (default 30). Convert the whole MGF and select features with `--feature-ids`. The converter uses every co-eluting feature to assign adducts ([M+Na]+, [M+NH4]+ and others) and to set aside multimers and in-source fragments, with the evidence in the manifest. Report those statuses and their related features rather than elucidating them as molecules. Adducts other than [M+H]+ are predicted with local ICEBERG, because the public atlas holds [M+H]+ only. `SOURCE_SCAN`/`SCANS` may be the MS1 apex and must not be treated as an MS2 scan. A `needs_energy` manifest row requires provider confirmation or an explicit `--energy` override. For Bruker Q-TOF, inspect the raw MS2 scan's precursor-specific absolute eV setting. For an existing `.ms` file, proceed directly.
2. Ask the user what collision energies they supplied and whether the labels are NCE or absolute eV. Do not infer the unit from the `.ms` headers, instrument, or numeric values; report any conflict between the user answer and headers. Run `msms-structure-elucidation run --input sample.ms --collision-unit NCE --output-dir results/sample` (or `--collision-unit eV` when confirmed). Supply `--formula` when known, or `--formulas-file` for a list. Otherwise the top three MSBuddy hypotheses are searched and recorded as inferred. MSBuddy mass tolerances follow the instrument: Q-TOF 10 ppm precursor / 20 ppm fragments, Orbitrap 5 / 10 ppm; an unrecognised instrument gets the Q-TOF values and a warning. Override with `--ms1-ppm`/`--ms2-ppm`; the values used are recorded as `mass_tolerance`. If MSBuddy proposes none, `run` searches PubChem for single-component, uncharged, closed-shell structures within the precursor tolerance (CHNOPS by default; `--formula-elements`) and searches up to three of their formulas, recorded as PubChem mass matches. If there is still no formula, report `needs_formula` (`next_step: review-frigid`): review the spectrum yourself (adduct, in-source fragment, isotope peak, noise), request formula evidence or a formula list, and decide whether FRIGID (step 5) is warranted.
3. Read `retrieval.json`, especially `status`, `formula_results`, and `energy_mapping`. Public atlas entries are precomputed ICEBERG 2.1 predictions for PubChem structures and omit licensed NIST structures. Convert confirmed NCE to eV, round both experimental and atlas eV to integers, and use only exact rounded matches. If any energy is absent for an atlas formula, local ICEBERG predicts all atlas structures for that formula at every supplied energy in resumable shards. Supply an ms-pred checkout and public or licensed ICEBERG weights; if missing, report `blocked_model_assets` and the underlying error. Inspect that every experimental energy contributed to the score. Similarity near or below 0.5 is a review trigger, not calibrated confidence. Explain `no_atlas_coverage` separately from weak matches; its `next_step: iceberg-pubchem` means predicting the formula's PubChem structures with `msms-structure-elucidation review --result results/sample/retrieval.json --proposals pubchem --model iceberg`.
4. When evidence is weak or important peaks remain unexplained, use `msms-structure-review` to propose novel SMILES from explicit matched/unmatched peaks. Validate formulas and duplicates, then check atlas matches before running GLACIER (default review model) or ICEBERG with supplied public or licensed checkpoints. Set `--ms-pred-dir` to the checkout so relative model scripts run correctly; the checkpoint preflight catches incompatible GLACIER atom feature widths. Use `.ms >instrumentation` or `--instrument`, and `--cuda-devices` or `MSMS_CUDA_DEVICES` for GPU. Convert NCE to rounded integer eV with `nce=False`. Model failure is fatal and prints the underlying error. If several experimental energies round to the same model eV, predict that eV once and compare it with each experimental spectrum. Simulated candidates record the model name and version (e.g. ICEBERG 2.1), ms-pred version, and checkpoint.
5. If no satisfactory candidate emerges, run `msms-subformulae` then `msms-denovo` with FRIGID. Keep FRIGID's interpreter and checkpoint paths separate from ms-pred; the setup script clones and installs FRIGID without modifying an existing checkout.
6. Always present the richer `msms-visualize` page as the primary result, including when `run` also wrote a basic `report.html`. Run `msms-structure-elucidation visualize --result results/sample/retrieval.json` and give the user its localhost URL. For several unknowns, pass every `retrieval.json` to one viewer so all of them are reviewed on a single page. The viewer shows ranked candidates, all paired collision energies, mirror spectra, and clickable predicted fragments; candidate decisions and fragment comments autosave to a separate `review_notes.json`. For a shareable snapshot with the same rich interaction, use `visualize --result ... --export review_report.html`.
7. For many features, run `msms-structure-elucidation batch --manifest converted/manifest.csv --output-dir results/batch` It processes several features at once in worker processes when CPU and RAM permit (`max_workers: auto`, up to 8, or the value `setup` saved), so atlas lookups run in parallel and the GPU is not left idle during one feature's CPU steps. Lower `--max-workers` if memory is tight. When every feature is done, batch exports one self-contained `review_report.html` for all results in the output directory and prints the `visualize` command; present that page (or the served viewer, `--serve`) as the batch result. `--no-review-page` skips it. Report candidate source, formula source, entropy score, explained intensity, positional-isomer ambiguity, matched and unexplained peaks, model asset provenance, per-formula status, and limitations. Preserve candidate evidence in JSON and HTML.
