# MS/MS structure elucidation

1. For raw files, use `msms-preprocess`, `msms-inspect`, or `msms-feature-detect` to export a selected MS/MS feature in ms-pred `.ms` format. For an existing `.ms` file, proceed directly.
2. Ask the user what collision energies they supplied and whether the labels are NCE or absolute eV. Do not infer the unit from the `.ms` headers, instrument, or numeric values; report any conflict between the user answer and headers. Run `msms-structure-elucidation run --input sample.ms --collision-unit NCE --output-dir results/sample` (or `--collision-unit eV` when confirmed). Supply `--formula` when known. Otherwise MSBuddy proposes formula hypotheses, recorded as inferred. Mass tolerances follow the `>instrumentation` line of the `.ms` file: Q-TOF 10 ppm precursor / 20 ppm fragments, Orbitrap 5 / 10 ppm; an unrecognised instrument gets the Q-TOF values and a warning. Override with `--ms1-ppm`/`--ms2-ppm`; the values used are recorded as `mass_tolerance`. If MSBuddy proposes none, `run` searches PubChem for single-component, uncharged, closed-shell structures whose monoisotopic mass is within the precursor tolerance (CHNOPS by default; `--formula-elements`) and uses those formulas, recorded as PubChem mass matches.
3. Read `retrieval.json` and the offline `report.html`. Public atlas entries are precomputed ICEBERG 2.1 predictions for PubChem structures and omit licensed NIST structures. Atlas energies are in eV. Convert confirmed NCE using ms-pred's precursor m/z conversion, pair every experimental energy with a nearby atlas energy within 2 eV, and average ms-pred entropy similarity across all paired energies. Inspect the recorded energy pairs and unmatched energies; do not silently score one energy. Similarity near or below 0.5 is a review trigger, not a calibrated confidence threshold.
3a. Follow `next_step` in `retrieval.json` when retrieval ranked nothing:
   - `iceberg-atlas`: the ICEBERG Atlas has structures for the formula, but none at a collision energy within 2 eV of the experiment. Predict them at the experimental energy: `msms-structure-elucidation review --result results/sample/retrieval.json --proposals atlas --model iceberg --gen-checkpoint ... --inten-checkpoint ...` (GLACIER with `--model glacier --checkpoint ...` when its weights match the installed ms-pred).
   - `iceberg-pubchem`: the formula has PubChem structures but no ICEBERG Atlas entry. Predict them with `--proposals pubchem` (capped by `--max-structures`, default 500).
   - `retry-retrieval`: the atlas download or ranking failed; rerun `run` for that unknown.
   - `review-frigid`: neither MSBuddy nor PubChem has a formula for the precursor. Review the spectrum yourself (adduct, in-source fragment, isotope peak, noise); if it is a genuine unknown, decide whether to generate structures de novo with FRIGID (step 5) and tell the user why.
   Set `MSMS_CUDA_DEVICES=0` to run GLACIER or ICEBERG on a GPU.
4. When evidence is weak or important peaks remain unexplained, use `msms-structure-review` to propose novel SMILES from explicit matched/unmatched peaks. Validate formulas and duplicates, then check atlas matches before running GLACIER (default) or ICEBERG with supplied public or licensed checkpoints. For model calls, convert every confirmed NCE value to eV using precursor m/z, round eV to an integer, and pass those integers with `nce=False`. If several experimental energies round to the same model eV, predict that eV once and compare it with each experimental spectrum.
5. If no satisfactory candidate emerges, run `msms-subformulae` then `msms-denovo` with FRIGID. Keep FRIGID's interpreter and checkpoint paths separate from ms-pred; the setup script clones and installs FRIGID without modifying an existing checkout.
6. For interactive fragment inspection and human review, run `msms-visualize` on the saved `retrieval.json`; for several unknowns, pass every `retrieval.json` to one viewer so all of them are reviewed on a single page. Its localhost webpage displays ranked candidates, all paired collision energies, mirror spectra, and annotated fragments. Save candidate decisions and fragment comments on the page to a separate `review_notes.json`.
7. Report candidate source, formula source, score, matched peaks, unexplained peaks, model asset provenance, and limitations. Preserve all candidate evidence in the JSON and HTML output.
